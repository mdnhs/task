# BA SRS v1.3 vs the previous SRS and the app (9 Nov 2026)

Compares the BA's SRS v1.3 (5 Nov 2026, now `SRS.md`) with the version it replaced (28 Oct 2026) and the front end as built.
"Built" means a front-end mock (JSON data, in-memory stores). Nothing has a real backend yet. The earlier comparison is `srs-diff-2026-10-28.md`.

## 1. What changed in the spec

| Topic | 28 Oct 2026 | v1.3 |
| --- | --- | --- |
| Modules and phases | Ten modules, five phases | Twelve modules, six phases. New Phase 1B between Phase 1 and Phase 2 |
| New modules | None | M1A Rostering (35 FR-RS, 6 AC-RS), M1B Time & Attendance (18 FR-TA, 5 AC-TA), M1C Payroll processing (19 FR-PY, 5 AC-PY) |
| First client needs | CR-01 to CR-06 | Adds CR-07 to CR-11 (roster by location, individual start times, location-only supervisor, clock in and out, full payroll) |
| Payroll | Module 8, provider integration, Phase 4 | Module 1C, full pay run in the app, statutory steps through a provider, Phase 1B. Number 8 is kept free |
| Roles | Ten | Adds Location supervisor and Payroll officer |
| Published rosters (v1.3) | Not covered | Locked for location supervisors; they send change requests; higher-level users edit with a reason (FR-RS-35 to 39) |
| Repeat roster (v1.3) | Not covered | One-step repeat, re-check of every copied shift, auto-repeat, saved templates (FR-RS-26 to 29) |
| Phase 4 | Money, time and payroll | Money and client delivery: M6 and M7 only |
| Open questions | Q1 to Q11 | Adds Q12 to Q17 |

Requirement counts for M0, M1, M2, M3, M4, M5, M6, M7, M9 and the NFRs are unchanged. Text changes outside the new sections: the Finance user row, the §2.5 provider assumption, FR-M4-10 (payslips now Module 1C), §3, §12 and the §15 intro.

## 2. The app against the new modules

| Area | In the app | Missing |
| --- | --- | --- |
| Locations (FR-RS-01..04) | None; `site` is free text on roster gaps and incidents | Location records with address, map pin, clock-in zone, shift templates, staffing targets, required licences |
| Shifts (FR-RS-10, 20, 21) | Patterns, assignment per person, week grid, shifts across midnight (`lib/shifts.ts`) | Day-by-day roster per location, individual start and end per person |
| Draft, publish, lock (FR-RS-23, 24, 35..37) | None | All of it, with change requests and history |
| Repeat and templates (FR-RS-26..29) | None | All of it |
| Location access (FR-RS-30..34) | None; filtering is by department | Location supervisor role and location grants |
| Gaps and cover (FR-RS-12, 42, 43) | Roster gaps and cover (`/staff-rosters`), partial | Staffing targets, open shifts, swap approval |
| Leave, availability, working-time rules (FR-RS-41, 44) | None | All of it |
| Time & Attendance (FR-TA-*) | None; the Attendance tab lists incidents, not clock events | All of Module 1B |
| Payroll (FR-PY-*) | Payroll Issues only, close to FR-PY-24, not linked to a payslip line | Pay profiles and rules, pay runs, payslips, SEPA file, journal |
| Roles | Payroll User maps to Payroll officer | Location supervisor, office roster manager |
| Plan entitlements (FR-M0-15) | `billing/entitlements.json` maps `payroll` to `M8` | Separate entitlements for M1A, M1B, M1C |

The rosters incident/cover model stays (product owner decision, 28 Oct 2026); the new roster has to connect to it.
