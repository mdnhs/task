# New BA SRS vs SRS v1.2 and the app (28 Oct 2026)

Compares the new BA SRS (now `SRS.md`) with SRS v1.2 (now `SRS-v1.2-built.md`) and the front end as built.
"Built" means built as a front-end mock (JSON data, in-memory stores). Nothing has a real backend yet.

## 1. What changed at product level

| Topic | SRS v1.2 (OpsDesk) | New SRS (AI Business OS) |
| --- | --- | --- |
| Product | One ops app for a Security and Cleaning client, SaaS-ready | Modular SaaS for SMEs (5 to 250 staff). Ten modules, each sold on its own |
| Modules | One app with sections | M0 Platform, M1 Tasks and shift reports, M2 AI assistant, M3 Automation, M4 HR, M5 CRM, M6 Projects, M7 Finance, M8 Payroll, M9 BI |
| Build order | Delivery phases | Five gated phases. First client goes live after Phase 1 (M0 + M1 only) |
| Core loop | Daily end-of-day report per department at 5:30 PM, 10 sections | End-of-shift report per member, pre-filled from that member's shift tasks, deadline after shift end |
| Organisation | Departments | Teams and reporting lines; a member can be in several teams and has one primary manager |
| Roles | owner, admin, manager, ops, supervisor, employee, hr, payroll, auditor, platform | Platform super admin, owner, admin, manager, member, HR officer, sales user, finance user, client guest, auditor. Roles are templates admins can clone |
| IDs | FR-TASK-01, FR-REP-12, OC-nn | FR-Mx-nn, AC-Mx-nn, CR-nn, NFR-nn, Q1–Q11 |
| Locale | en-GB, GBP, Europe/London in seed data | Ireland first: Europe/Dublin, EUR by default (FR-M0-20) |
| Mobile | Responsive web on Android | A real Android app with push, offline drafts and lock-screen audio |
| Module switching | Role-based access only | Plan entitlements. A module not in the plan is hidden in the UI and refused by the API (FR-M0-15) |

### Later phases (no front-end work for Phase 1)

- **M2 AI assistant:** confirmation cards before any action, priority engine with reasons, voice, meeting transcripts with consent, knowledge base with citations, AI on/off per feature and usage limits. v1.2 has a mock chat panel only.
- **M3 Workflows:** visual builder, triggers and actions, approvals, run log, retries, templates. Nothing in v1.2.
- **M4 HR:** employee profiles, org chart, onboarding checklists, leave with Irish holidays, reviews, training, self-service, masked PPSN and bank fields, retention.
- **M5 CRM:** leads, deals, pipelines, quotes, consent, CSV import.
- **M6 Projects Pro:** budgets, capacity, billable time, client portal, risks.
- **M7 Finance:** invoices with VAT, credit notes, expenses, purchase requests, accounting sync, e-invoicing.
- **M8 Payroll:** pay data and approvals sent to an Irish payroll provider. The platform must not claim to calculate PAYE, PRSI or USC.
- **M9 BI:** dashboards, report builder, KPIs, scheduled exports, shift-report KPIs.
- **NFR-01–18:** EU hosting, AES-256, a 12-hour idle timeout, 99.9% uptime, RPO 1 h / RTO 4 h, WCAG 2.2 AA, pen test before go-live, tenant-isolation tests block release.

## 3. Changed requirements (v1.2 says it differently)

| Topic | v1.2 / app today | New SRS |
| --- | --- | --- |
| Daily report | One report per department per day, deadline 17:30 (`public/data/shell/org.json`), 10 fixed sections (§4) | One report per member per shift. Deadline is set relative to shift end (assumed 1 hour, Q7). Built from that member's shift tasks |
| Who reports | Report owners per department | Manager picks which members report (per member, team default) |
| Review statuses | Draft, submitted, resubmitted, returned, accepted | Submitted, late, missing, accepted, returned |
| Evidence | Yes/no `evidenceRequired` flag; kinds image, file, link, note; review accept / reject / request info (FR-TASK-14) | Three-level rule, type allow-list, minimum count, instruction, review mode, versions, read-only after submit |
| Reviewer | Reviewer role in general | The task creator picks the reviewer per task (creator, manager or named person) or auto-accept |
| Task removal | "Cancel task" | Archive, recoverable for 30 days |
| Recurring | Daily, weekdays, weekly, monthly (built) | Daily, weekly, **per shift**, custom |
| Templates | Task templates (built, in memory) | Templates also carry evidence defaults |
| Exports | Report PDF/XLSX for one report or a day (built) | PDF and CSV for a date range (FR-M1-31); CSV/Excel/PDF and scheduling come later in M9 |
| Notifications | In-app, email, WhatsApp channels; reminders before 17:30 (mock) | In-app, email, **Android push**; per-user preferences **and quiet hours**; lock screen shows counts only |
| Locale | en-GB, GBP, Europe/London | Europe/Dublin, EUR default; English (Ireland) |
| Drive | Policy text on the integrations card ("Office PCs only · blocked on Android") | Real device register plus a policy checked on every request; Drive buttons hidden on untrusted devices |
| Sign-in | Email/password mock; 2-step toggle in account | Google/Microsoft SSO, TOTP; admin can force MFA |
| AI assistant | In the core app (mock) | Paid add-on (M2). M1 gets only the rules-based Today summary and summaries |
| Branding, platform console, billing | Detailed in v1.2 (§3.24–3.26) | Covered briefly by FR-M0-14/15 and the platform super admin role. Branding is not mentioned |
