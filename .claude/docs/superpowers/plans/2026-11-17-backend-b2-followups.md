## Controller rulings
- Ruling B1: the relay hint table is `event_relay_hints(tenant uuid primary key)` — column named `tenant`, not `tenant_id`, holds ids only, documented as the single RLS exception; the T2.0 guard keys on the column name tenant_id. Cost if wrong: a guard blind spot for that one table (ids only).
- Ruling B2: subscriber signature is `(e: DomainEvent, ctx: { tx: TenantTx; deps: Deps }) => Promise<void>`; the delivery row insert and the handler's DB effects share ctx.tx; external side effects (mail/push) go through queue jobs enqueued after commit. Cost: none.
- Ruling B3: each task adds its Deps member and a default fake in testApp(); server.ts/makeDeps wires the real adapter from env. Cost: none.
- Ruling B4: every task with new path-param routes adds SPECS entries (same actor+body for control and B-walk, resource-specific 404 code). Cost: none.
- Ruling B5: T2.1 adds the worker entry and an `api/Dockerfile` CMD switch (`node … server.ts` default, `worker.ts` via `command:` override); later tasks just register jobs. Cost: none.
- Ruling B6 (load-bearing for T2.2–T2.4 callers): fold into T2.0 fix round: v1 opening becomes opt-in per call (`open(s, ring, aad, { allowV1: true })`, email path only); SECRETS_KEY_ID checked with Object.hasOwn. Cost: tiny.
- Ruling B7: fold into the same round (GDPR/robustness, cheap): relay error logs carry only err.name + cause.code (no Drizzle message with params); per-tenant try/catch in relayOnce; document lock order rule "recordAudit first, publish last". Cost: small.
- Ruling B8: accept notify(tx, tenantId, input, deps, enqueue) signature change (locked interface updated) and security bypass for push too (security alerts should reach the user immediately). Cost: none.
- Ruling B9 (design): staging-key flow — POST policy targets `u/<tenant>/<fileId>` only; complete → server-side CopyObject to `t/<tenant>/<fileId>` (key never in any POST policy) + delete staging; scan and serve only the `t/` copy; sha256 recorded at scan; downloads need no ETag recheck. Extension enforcement: stored download name gets the canonical extension for the mime (replace/append). Fold minors: reject names with lone surrogates (422 invalid_name); scan job ids include a per-attempt nonce (no BullMQ dedupe trap); delete-object job id unique per request. Cost: one round.
- Ruling B10: R2 is S3-compatible but does not support presigned POST policy uploads (PostObject) nor object versioning → T2.3 switches to presigned PUT to the staging key (expires 300 s, signed Content-Type and Content-Length so the client must send exactly the declared values), complete's HEAD check (size/type) stays the authority, oversize/mismatch → delete staging + 422; region "auto"; endpoint https://<account_id>.r2.cloudflarestorage.com; path-style. Tests keep MinIO but use only the operations R2 supports (PUT/GET/HEAD/DELETE/CopyObject presigned or server-side). R2 credentials remain deploy env (infra secrets), not admin-managed. Cost: client upload flow becomes a single PUT (simpler).
- Ruling B11: platform_storage_settings singleton (provider 'r2', account_id, bucket, access_key_id, secret_access_key_ciphertext sealed v2 with AAD "platform.storage.r2.secret_access_key", public endpoint derived from account_id, updated_by/at); service get/set/test like platform-email (never returns the secret, keyLast4 only, platform audit hook); S3Storage reads config via a StorageConfigSource with ≤60 s cache + invalidate(); env S3_* only as bootstrap fallback / tests; production with no config → storage calls fail closed with 503 problem+json `storage_not_configured`. HTTP routes + UI land in B3 (platform settings) — B3 plan amended. Cost: small extra in T2.3.
- Ruling B12: indexDocument takes now (clock) as 3rd arg — consistent with deps.clock rule. Cost: none.
- Ruling B14: fold Minor 7 (search doc removal ordering for owned files) into this round (erase completeness). Audit forward-fix: audit before/after store ids + tenant-keyed HMAC(normalised email) (key derived from keyring, purpose "audit.email_hmac"), never raw emails; existing rows untouched (documented as retention under legitimate interest in RoPA notes). Cost: one round.
- Ruling B15 (fold into round 2; data-loss/GDPR-duty risks): erase retry → 409 `subject_rejoined` if the subject holds a membership created after the request; export block only considers erases completed after the current membership's joined_at; sweep includes non-active tenants and isolates per-tenant failures (try/catch). Cost: small.
- Ruling B16 (fix wave scope): Important 1 (a nonce jobIds for re-hold/retry, b quietWindow guarantees endsAt > now and not quiet at endsAt — step past DST gaps, c notification.sweep every 5 min re-enqueueing queued/held past send_after + 2 min with nonce ids, d `sending` status + claimed_until lease), Important 2 (dsr.sweep expires completed exports past TTL), plus cheap cross-cutting minors: worker `failed` handler and app onError log only safe codes (no err.message), Redis producer enableOfflineQueue:false + bounded retries (HTTP never hangs on Redis outage; post-commit add failures logged and left for sweepers), logging push adapter returns skipped/no_provider (not sent), stale "presigned POST" comments. Everything else → follow-ups doc.
