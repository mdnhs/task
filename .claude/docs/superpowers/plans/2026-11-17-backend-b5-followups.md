| F2 | **A shift belongs to the calendar date it STARTS on, in the pattern's own zone** (`shift_date`; the tenant zone unless the pattern names one). A 22:00–06:00 shift that starts Sat 24 Oct reports on **24 Oct**, even though it ends on the 25th. The domain `shiftWindow().date` is changed to that pattern-local date (it was the tenant-local date, which differs only for a pattern whose zone differs from the tenant's and made `shiftsOn` and the report key disagree). | F3 | `start_at`, `end_at`, `due_at` are UTC instants computed by the domain engine from the pattern's wall times (`wallToEpoch`: a gap time moves forward, an ambiguous time takes the EARLIER instant, D3) and **stored in the report row when it is first saved**. They are never re-derived from a wall string (a wall time in the repeated hour does not identify an instant). `due_at = end_at + dueAfterMinutes` as epoch minutes (real minutes), not wall arithmetic. A pattern edit changes only occurrences not yet saved; saved reports keep their snapshot. | Review Focus #2; a 22:00–06:00 night is 9 h on 24 Oct 2026 and 7 h on 27 Mar 2027. | a pattern edit does not touch reports already started (a manager must return and the member resubmit) |
| F4 | **A draft is virtual until first saved.** `GET /v1/shift-reports/current` and the inbox compute shifts from assignments and patterns; `POST /v1/shift-reports/open {patternId, date}` get-or-creates the member's own report row (idempotent on `unique (tenant_id, user_id, pattern_id, shift_date)`). Every `{id}` path param is a real row (D2). A shift nobody touched costs no row, and the deadline job works from assignments plus a ledger, not from report rows. | 250 users × several shifts a day would otherwise pre-create thousands of empty rows. | the inbox merges virtual rows in memory (range ≤ 31 days) |
| F5 | Report scope uses D5 semantics through `reportScope(role, me)` and `effectiveReportScope`: staff-home → **own**; manager-home with `reportScope: "team"` → **me + my direct reports** (one level, same as tasks); other manager-home → **all**. | F7 | **Submit is atomic, versioned and idempotent.** Body `{ version, requestId }` (`requestId` = client uuid). One tx: validate against the team template, lock rows, apply one `applyTaskUpdate` per row, write a frozen `shift_report_versions` snapshot, status → `submitted`. A replay with the same `requestId` returns the stored result (200, no new version); a stale `version` is 409 `version_conflict`. A report that is `submitted` or `accepted` rejects edits and re-submit (409 `report_locked`); `returned` may be edited and resubmitted (new version, `v+1`). | NFR-08 retries on 4G; FR-M1-27. | a client without `requestId` gets 400 |
| F8 | **Time on resubmit is a delta.** The update id of a row is `<reportId>.v<n>.<ref>` (new per version, so status changes re-apply), but the minutes logged are `max(0, new − previous version's minutes)` per row. ## B6 (frontend adapter): mandatory

- **Export rows drift.** The FE `features/reports/export-rows.ts` and the domain builder `packages/domain/src/report-export.ts` are two copies. Switch the FE to the domain builder, or add a parity test that fails when they differ.
- **Report scope.** F5 is one level (me plus direct reports); the FE `teamOf` is direct AND indirect. Align the seed or the adapter.
- **Template by team NAME.** The report template matches the team by name, so a team rename silently changes which template applies. Move to a team id when the settings UI is built.
- **`seriesId`.** The DTO `seriesId` is a uuid; the FE uses a ref. Map it in the adapter.
- **`ReportSchema` catchall.** The report DTO uses a `catchall` for extra answers; B6 needs a typed schema (generated client types).
- **`canVerify`.** Every FE call site (task-actions, evidence-panel, task-detail) must pass the FULL assignee list (D8).
- **Export status `expired`.** The DTO status can be `expired` (a done export past its 7 days); the FE enum must include it.
- **Today update.** `POST /v1/today/updates` needs the server working day as `dayKey` (422 `invalid_day_key` otherwise). The browser queue id format (`today:<day>:<ref>:<action>`) is unchanged; only the server adds `:<actorId>`, and `handledToday` still matches by prefix.
- **Report row notes.** A report row note is no longer copied to the task history (H4): the task page shows the neutral line only; the note is read from the report.
- **Attention workflow (G1).** The manager attention decide / outstanding workflow, coverage and expiring documents are B8/B11; the FE buttons stay mock until then.

## Known limitations and follow-ups

| Limitation | FOLLOW-UP |
|---|---|
| DSR erase leaves copies of an erased member's report data in OTHER managers' exports (stored files) for up to 7 days; the erased member's own exports are removed with the membership. | Document in the DSR notice; optionally expire exports that hold an erased member's reports when the erase runs (B11). |
| DSR erase versus a reviewer's `notify` can deadlock in theory; the loser gets 409 `retry` (40P01 maps to a retryable 409) and the client repeats the request. | Keep the retry contract; revisit the lock order if it is ever seen in production logs. |
| A team that has archived patterns cannot be deleted (`team_has_shifts`): archiving keeps the pattern row. | Allow delete when no report references the patterns, or add a purge of archived patterns (B8). |
| The PDF export is Latin-1 only: Bengali and other characters print as `?` (smart punctuation is mapped to ASCII). | Embed a Unicode font (for example Noto Sans) in the PDF encoder. |
| A pattern edit recomputes the virtual rows and the alerts of unopened past shifts (saved reports keep their snapshot, F3). | Say so in the pattern edit UI; optionally freeze past dates. |
| The sweeps (`report.export-sweep`, report alerts, recurrence, retention) iterate ALL tenants in one job. | Shard per tenant batch when the tenant count grows (B7 load work). |
| `completed_at` is off by up to an hour inside the repeated DST hour (25 Oct 2026 in Europe/Dublin): a report-driven completion reads a wall string. | Pass the instant instead of the wall string (needs a domain contract change). |
| Today compares wall-clock strings (up to an hour off inside the repeated hour); the dashboard and attention use instants. | Compare instants in `loadToday`. |
| Multi-instance cache staleness of at most 30 s (G2): a write on one instance busts only that instance's keys; worker-job writes reach the cache only through the TTL. | A Redis-backed bust or a version stamp when a second instance is deployed (B7). |
| Export job crash points (H5): after the claim or during the build nothing is written and the lease lapses (the sweep re-runs it); after the storage write and before the final commit an object exists with no files row, and the re-run overwrites the same key (a failure removes it with `dropUncommittedObject`); the final commit is atomic. The lease is renewed after every page. | None needed at the caps. |
| `npm audit --omit=dev` reports `uuid < 11.1.1` (moderate, buffer bounds in v3/v5/v6 when `buf` is passed) under `exceljs` 4.4.0; exceljs calls uuid v4 without a buffer, so the path is not reached. No advisory names `jspdf` or `jspdf-autotable`. The only automatic fix is a downgrade to exceljs 3.4.0 (breaking), not taken. | Re-check when exceljs ships a release that depends on uuid >= 11.1.1. |
