## B6 (frontend adapter) notes

- The DTO omits `parentRef` and sets `parentId: null` when the parent is outside the caller's task scope (fix wave I4). The FE parent/subtask logic must handle a missing `parentRef`.
- The DTO `seriesId` is a uuid; the FE uses a ref. Map it in the adapter.
- `POST /v1/tasks` takes no `repeat`: creating a repeating task is two calls (create, then `PUT /repeat`), not atomic.
- Every FE `canVerify` call site must pass the FULL assignee list (D8), so co-assignee managers do not see a Verify button. Today task-actions, evidence-panel and task-detail pass only the primary assignee.
- The DTO carries the ISO `dueAt` and `startAt`. For an unchanged date send the ISO instant back, not the wall time (see the DST fold below).
- `409 retry` can now come from any task write: repeat the same request once.

## B11 backlog

- Unattached upload sweep: voice, evidence and attachment uploads that never get attached persist until the task is purged.
- Soft-deleted `files` rows keep name and owner until the retention policy (names can be personal data).
- AI module: exclude `purpose = 'task_voice'` (and every `task_` purpose) at the source; the guard today is static on voice files only.
- The dependency cycle check loads all tenant edges (O(E)); replace with a recursive CTE when a tenant has many edges.

## Documented behaviour (E14, no code change)

- DST fold: a wall time inside the repeated hour (25 Oct 2026, 01:30 in Europe/Dublin) maps to the FIRST instant when it round-trips. B6 should send the ISO instant for unchanged dates.
- DSR erase leaves pseudonymous ids (not names): `evidence_rule.reviewer`, `proposal.by`, the assignee ids inside `task_history.changes`, and `voice_meta.recordedBy`.
